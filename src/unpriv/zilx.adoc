[[ext:zilx]]
=== ext:zilx[] Extension for Integer Indexed Loads, Version 0.1

The ext:zilx[] extension provides integer load instructions that compute
their effective address from a base register and an index register.
The extension defines unscaled indexed loads and scaled indexed loads.
On RV64, the extension also defines forms that zero-extend the low 32 bits
of the index register before forming the effective address.

[#norm:Zilx_no_new_state]#The ext:zilx[] extension adds no architectural
state, CSRs, or memory-ordering rules.#

==== Indexed Load Classes

Each ext:zilx[] instruction reads a base operand in _rs1_ and an index
operand in _rs2_, computes an effective address, loads a byte, halfword,
word, or doubleword from memory, and writes the extended load result to _rd_.

[#norm:Zilx_addr_width]#Effective addresses are computed using XLEN-bit
two's-complement address arithmetic, and address arithmetic overflow is ignored.#

[#norm:Zilx_unscaled_ea]#For an unscaled indexed load, the effective address is
the low XLEN bits of _X[rs1]_ + _X[rs2]_.#

[#norm:Zilx_scaled_ea]#For a scaled indexed load, the effective address is the
low XLEN bits of _X[rs1]_ + (_X[rs2]_ << _log2(access-size)_), where
_access-size_ is the number of bytes loaded by the instruction.#

[#norm:Zilx_uw_index]#For an RV64 indexed load whose mnemonic ends in
`.uw`, the index operand used in address formation is zero-extended from
_X[rs2][31:0]_ to 64 bits before any scaling is applied.#

[#norm:Zilx_rd_x0]#An ext:zilx[] load with _rd_=`x0` is executed as any
other ext:zilx[] load, including effective-address formation, memory access,
and exception checks, but the loaded value is discarded.#

There is no scaled byte-load form because scaling a byte index by the loaded
data size would not change the index value.

==== Load Semantics

[#norm:Zilx_load_semantics]#Except for the effective-address calculation,
each ext:zilx[] instruction behaves as the corresponding base integer load
of the same access size and signedness.#

[#norm:Zilx_sign_zero_extension]#Signed ext:zilx[] load forms sign-extend the
loaded value to XLEN, and unsigned ext:zilx[] load forms zero-extend the
loaded value to XLEN.#

[#norm:Zilx_exceptions_ordering]#An ext:zilx[] instruction follows the same
exception, address-alignment, access-fault, page-fault, PMP, PMA, privilege,
atomicity, and memory-ordering rules as the corresponding base integer load
executed at the same effective address.#

==== Assembly Syntax

The assembly syntax for ext:zilx[] instructions is:

[source,asm]
----
mnemonic rd, (rs1), rs2
----

For example:

[source,asm]
----
lxw      a0, (a1), a2
lxw.s    a0, (a1), a2
lxw.uw   a0, (a1), a2
lxw.s.uw a0, (a1), a2
----

The `.uw` suffix affects only the interpretation of the index operand during
effective-address formation; it does not affect whether the loaded memory
value is sign-extended or zero-extended.

==== Encodings

ext:zilx[] instructions use the `LOAD` major opcode with _funct3_=`111`.

[wavedrom, zilx-indexed-load-encoding, svg]
....
{reg: [
  {bits:  7, name: 0x03,   attr: ['LOAD']},
  {bits:  5, name: 'rd',   attr: ['dest']},
  {bits:  3, name: 0x7,    attr: ['ZILX']},
  {bits:  5, name: 'rs1',  attr: ['base']},
  {bits:  5, name: 'rs2',  attr: ['index']},
  {bits:  3, name: 'type'},
  {bits:  1, name: 0},
  {bits:  1, name: 'u'},
  {bits:  2, name: 'width'},
]}
....

[#norm:Zilx_common_encoding]#All ext:zilx[] instructions are encoded with
the `LOAD` major opcode, _funct3_=`111`, and bit 28 equal to zero.#
[#norm:Zilx_bit28_rsv]#Encodings in the ext:zilx[] encoding space with bit 28
equal to one are reserved.#

The _width_ field encodes the access size.

[%header,cols="^2,^2,4"]
|===
|_width_
|Access size
|Load type

|`00`
|1 byte
|byte

|`01`
|2 bytes
|halfword

|`10`
|4 bytes
|word

|`11`
|8 bytes
|doubleword

|===

[#norm:Zilx_width_access_size]#The _width_ field selects the number of bytes
loaded by the instruction; _width_=`11` is RV64-only.#

The _u_ bit selects the extension applied to the loaded memory value.

[%header,cols="^1,4"]
|===
|_u_
|Load-result extension

|`0`
|sign-extend the loaded value to XLEN

|`1`
|zero-extend the loaded value to XLEN

|===

[#norm:Zilx_u_bit]#The _u_ bit selects whether the loaded memory value is
sign-extended or zero-extended to XLEN.#

The _type_ field selects the address-formation mode.

[%header,cols="^2,5,4"]
|===
|_type_
|Address-formation mode
|Availability

|`010`
|unscaled indexed load
|RV32 and RV64

|`011`
|unscaled indexed load with zero-extended 32-bit index
|RV64 only

|`100`
|scaled indexed load
|RV32 and RV64

|`101`
|scaled indexed load with zero-extended 32-bit index
|RV64 only

|===

[#norm:Zilx_type_field]#The _type_ field values `010`, `011`, `100`, and
`101` select the ext:zilx[] address-formation modes shown in the preceding
table; all other _type_ field values are reserved.#

[#norm:Zilx_scaled_byte_rsv]#The encodings with _type_=`100` or _type_=`101`
and _width_=`00` are reserved.#

[#norm:Zilx_rv32_rsv]#On RV32, encodings with _width_=`11`, with
_type_=`011`, or with _type_=`101` are reserved.#

[#norm:Zilx_lxwu_rv32_rsv]#On RV32, word-load encodings with _u_=`1` are
reserved because a 32-bit unsigned load result is indistinguishable from a
32-bit signed load result.#

===== insn:lxwu.s.uw[]

Synopsis::
Load scaled indexed word unsigned with unsigned word index

Mnemonic::
lxwu.s.uw _rd_, (_rs1_), _rs2_

Description::
[#norm:lxwu-s-uw_op]#This RV64-only instruction computes the effective address
as _X[rs1]_ + (_zext32(X[rs2])_ << 2). The word at the effective address is
loaded, zero-extended to 64 bits, and written to _rd_.#

Included in: ext:zilx[]

===== insn:lxd.s.uw[]

Synopsis::
Load scaled indexed doubleword with unsigned word index

Mnemonic::
lxd.s.uw _rd_, (_rs1_), _rs2_

Description::
[#norm:lxd-s-uw_op]#This RV64-only instruction computes the effective address
as _X[rs1]_ + (_zext32(X[rs2])_ << 3). The doubleword at the effective address
is loaded and written to _rd_.#
