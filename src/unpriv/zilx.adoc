[[ext:zilx]]
=== ext:zilx[] Extension for Indexed Integer Load Instructions, Version 0.1

The ext:zilx[] extension provides integer load instructions that compute
their effective address from a base register and an index register.
The extension defines unscaled indexed loads and scaled indexed loads.
On RV64, the extension also defines scaled loads that zero-extend the low
32 bits of the index register before scaling and forming the effective
address.

[#norm:Zilx_no_new_state]#The ext:zilx[] extension adds no architectural
state, CSRs, or memory-ordering rules.#

==== Indexed Load Classes

[#norm:Zilx_operand_roles]#Each ext:zilx[] instruction uses _rs1_ as the
index operand and _rs2_ as the base operand, computes an effective address,
loads a byte, halfword, word, or doubleword from memory, and writes the
extended load result to _rd_.# The operand roles match the shift-add
instructions of the ext:zba[] extension, in which the shifted operand is
_rs1_ and the added base is _rs2_.

[#norm:Zilx_addr_width]#Effective addresses are computed using XLEN-bit
two's-complement address arithmetic, and address arithmetic overflow is ignored.#

[#norm:Zilx_unscaled_ea]#For an unscaled indexed load, the effective address is
the low XLEN bits of _X[rs2]_ + _X[rs1]_.#

[#norm:Zilx_scaled_ea]#For a scaled indexed load, the effective address is the
low XLEN bits of _X[rs2]_ + (_X[rs1]_ << _log2(access-size)_), where
_access-size_ is the number of bytes loaded by the instruction.#

[#norm:Zilx_uw_index]#For a scaled unsigned-word-index load, whose mnemonic
begins with `lxsuw`, the index operand is zero-extended from _X[rs1][31:0]_ to
64 bits before scaling; these instructions are defined only for RV64.#

[#norm:Zilx_rd_x0]#A ext:zilx[] load with _rd_=`x0` performs
effective-address formation, the memory access, and all associated exception
checks, but discards the loaded value.#

[NOTE]
====
Although semantically _rs1_ and _rs2_ are commutative in the unscaled indexed
loads, software should prefer to use _rs2_ as the base and _rs1_ as the offset.
This facilitates microarchitecture techniques that optimize the handling of
these operands differently.
====

Byte loads are provided only as scaled forms (mnemonic prefixes `lxs` and
`lxsuw`). Because the scale factor for a byte access is 1, an unscaled byte
load would be identical to the scaled byte load, so no unscaled byte load is
defined. For convenience, `lxb` and `lxbu` are provided as assembler
pseudoinstructions for insn:lxsb[] and insn:lxsbu[], respectively.

The following table lists the instruction classes defined by ext:zilx[].
In the effective-address column, _index_ denotes _X[rs1]_ and _base_ denotes
_X[rs2]_.

[%header,cols="4,5,4"]
|===
|Mnemonic prefix
|Effective address
|Index interpretation

|`lx*` (unscaled)
|_base_ + _index_
|_X[rs1]_

|`lxs*` (scaled)
|_base_ + (_index_ << _log2(access-size)_)
|_X[rs1]_

|`lxsuw*` (scaled, unsigned-word index, RV64-only)
|_base_ + (_index_ << _log2(access-size)_)
|_zext32(X[rs1])_

|===

==== Load Semantics

[#norm:Zilx_load_semantics]#Except for the effective-address calculation,
each ext:zilx[] instruction behaves as the corresponding base integer load
of the same access size and signedness.#

[#norm:Zilx_sign_zero_extension]#Signed ext:zilx[] load forms sign-extend the
loaded value to XLEN, and unsigned ext:zilx[] load forms zero-extend the
loaded value to XLEN.#

[#norm:Zilx_exceptions_ordering]#A ext:zilx[] instruction follows the same
exception, address-alignment, access-fault, page-fault, PMP, PMA, privilege,
atomicity, and memory-ordering rules as the corresponding base integer load
executed at the same effective address.#

==== Assembly Syntax

The assembly syntax for ext:zilx[] instructions is:

[source,asm]
----
mnemonic rd, (rs2), rs1
----

where _rs2_, written in parentheses, is the base register and _rs1_ is the
index register. Writing the base register in parentheses distinguishes the
base address from the index. For example:

[source,asm]
----
lxw    a0, (a1), a2   // a0 = mem[ X[a1] + X[a2] ]
lxsw   a0, (a1), a2   // a0 = mem[ X[a1] + (X[a2] << 2) ]
lxsuwd a0, (a1), a2   // RV64: a0 = mem[ X[a1] + (zext32(X[a2]) << 3) ]
----

==== Encodings

[#norm:Zilx_common_encoding]#ext:zilx[] instructions use the `AMO` major
opcode. The access width and signedness are encoded in _funct3_ using the same
encoding as base integer loads, and the addressing mode is encoded in
_funct5_.#

[wavedrom, zilx-indexed-load-encoding, svg]
....
{reg: [
  {bits: 7,  name: 'opcode', attr: ['7', 'AMO'], type: 8},
  {bits: 5,  name: 'rd',     attr: ['5', 'dest'], type: 2},
  {bits: 3,  name: 'funct3', attr: ['3', 'width/sign'], type: 8},
  {bits: 5,  name: 'rs1',    attr: ['5', 'index'], type: 4},
  {bits: 5,  name: 'rs2',    attr: ['5', 'base'], type: 4},
  {bits: 1,  name: 'rl',     attr: ['1', '0'], type: 8},
  {bits: 1,  name: 'aq',     attr: ['1', '0'], type: 8},
  {bits: 5,  name: 'funct5', attr: ['5', 'mode'], type: 8},
]}
....

[#norm:Zilx_aqrl_zero]#For all ext:zilx[] instructions the _aq_ and _rl_ bits
must be 0; encodings with _aq_ or _rl_ set are reserved.#

The _funct3_ field encodes the access width and signedness, reusing the base
integer load encoding.

[%header,cols="^2,4"]
|===
|_funct3_
|Access width and signedness

|`000`
|signed byte

|`001`
|signed halfword

|`010`
|signed word

|`011`
|doubleword (RV64-only)

|`100`
|unsigned byte

|`101`
|unsigned halfword

|`110`
|unsigned word (RV64-only)

|`111`
|_reserved_

|===

The _funct5_ field selects the addressing mode. In every ext:zilx[] encoding
_inst[28:27]_ is `10`, matching the load-reserved and load-acquire encodings.

[%header,cols="^2,5,3"]
|===
|_funct5_
|Addressing mode
|Availability

|`10010`
|unscaled indexed load (`lx`)
|RV32 and RV64

|`11010`
|scaled indexed load (`lxs`)
|RV32 and RV64

|`11110`
|scaled indexed load with zero-extended 32-bit index (`lxsuw`)
|RV64-only

|===

[#norm:Zilx_mode_encoding]#The addressing mode is selected by _funct5_:
`10010` selects the unscaled mode, `11010` selects the scaled mode, and `11110`
selects the scaled unsigned-word-index mode.#

[#norm:Zilx_mode_rsv]#All _funct5_ values other than `10010`, `11010`, and
`11110` are reserved within the ext:zilx[] encoding space.#

[#norm:Zilx_funct3_rsv]#In all ext:zilx[] addressing modes, _funct3_=`111` is
reserved.#

[#norm:Zilx_no_unscaled_byte]#In the unscaled mode (_funct5_=`10010`),
_funct3_=`000` (signed byte) and _funct3_=`100` (unsigned byte) are reserved,
because byte loads are provided only in the scaled modes.#

[#norm:Zilx_rv32_rsv]#On RV32, all encodings with _funct3_=`011` (doubleword)
or _funct3_=`110` (unsigned word), and all encodings in the scaled
unsigned-word-index mode (_funct5_=`11110`), are reserved.#

==== Instructions

[#insns-lxh,reftext="Load indexed halfword"]
===== insn:lxh[]

Synopsis::
Load indexed halfword

Mnemonic::
lxh _rd_, (_rs2_), _rs1_

Description::
[#norm:lxh_op]#The effective address is _X[rs2]_ + _X[rs1]_.
The halfword at the effective address is loaded, sign-extended to XLEN, and
written to _rd_.#

[#norm:lxh_enc]#`lxh` is encoded in the unscaled mode with
_funct5_=`10010`, _funct3_=`001`, _aq_=`0`, and _rl_=`0`.#

Included in: ext:zilx[]

[#norm:lxw_enc]#`lxw` is encoded in the unscaled mode with
